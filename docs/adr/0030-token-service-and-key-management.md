# ADR-0030: Access token service, key management and the production auth composition

- Status: Accepted (engineering default; key custody and KMS choice stay with ADR-0002)
- Date: 2026-10-11
- Spec refs: master prompt section 1, B1, B6, T5; ASVS 5.0 V6/V7/V9 (L2); MASVS AUTH
- Related: ADR-0029 (production composition), ADR-0026 (attestation, Proposed), ADR-0002 (residency, Proposed)

## Context
Production boot left auth blocked: no Postgres adapters, `DevTokenService` issuing opaque random strings, and a deny-all authenticator, so every shopper route answered 401. The master prompt fixes the token shape: JWT, 10 minutes, audience-scoped, with `amr`; refresh tokens opaque, device bound, 30 days, rotated on every use.

## Decisions
1. **Access token = JWT signed with EdDSA (Ed25519), `typ: at+jwt`, header `kid`.** Claims: `iss, sub, aud (buyer_api | seller_api | admin_api), iat, exp (<= iat + 600 s), jti, sid, amr[]`.
   - Options compared: (a) HS256 shared secret: every verifier can mint tokens, rejected. (b) RS256: larger keys and signatures, slower signing, and RSA/HMAC key-confusion history; the platform already verifies RS256 only for Apple/Google. (c) ES256: fine, but ECDSA needs a good nonce per signature. (d) EdDSA: deterministic signatures, 64-byte tokens signature, fast verify, no parameter choices. Chosen: (d), via `jose`.
2. **Verification is strict**: algorithm pinned to EdDSA, `typ` pinned, `kid` must be in the loaded key set (no fetching by header), headers `jwk, jku, x5u, x5c, x5t, crit, b64` rejected, issuer and audience checked, lifetime re-checked against the 10 minute cap, 30 s skew. A token for `seller_api` or `admin_api` never authenticates a shopper route.
3. **Revocation is immediate.** Every authentication also loads the session row (`auth_sessions`) and the user; a revoked session, a `sid` owned by someone else, or a non-active user is a 401. Cost: one indexed read per request, accepted for L2.
4. **Keys come from a port** (`TokenKeySource`, provider name `secrets.manager`). Production default is Unconfigured: `issue()` throws `ProviderNotConfiguredError` (503) and `authenticate()` returns null (401). Material is validated with Zod (OKP/Ed25519, unique kids, active key has a private part). The service reloads on a TTL (default 60 s) so a rotation needs no restart; a transient source failure after a good load keeps serving the last good set; a never-loaded service fails closed.
5. **Rotation runbook**: add the new key, set `activeKid` to it, keep the old public key for at least 15 minutes (token TTL plus skew), then remove it. `JoseTokenService.jwks()` returns the public set (OKP, `use: sig`, `alg: EdDSA`) and is ready to serve at `/.well-known/jwks.json`; no endpoint is exposed yet because no external verifier exists.
6. **Refresh tokens** (unchanged domain, now persisted): 256-bit random, only `SHA-256("refresh:v1:" + token)` stored (`sessions.refresh_hash`), device (install id) bound, 30 days, rotated on every use. A rotated token presented again, or a token presented from another install, revokes the whole family (`session_families.revoke_reason`), ends the session and emits `session.revoked` with `notify_user = true`. Concurrent rotations are serialised by a row lock on the family (`SELECT ... FOR UPDATE`), the loser gets 409.
7. **P2/P3 fields** go through a `FieldCipher` port (`kms.envelope`): AES-256-GCM envelope with the column as AAD, and HMAC-SHA-256 blind indexes (`phone`, `identity:<provider>`, `otp-device`). Production default is Unconfigured, so every operation that touches a phone, DOB or e-mail answers 503. `LocalKeyFieldCipher` (one 32 byte master from the secret port, derived sub-keys) is the only concrete implementation until a KMS adapter exists. It is acceptable for synthetic data only (ADR-0002 not accepted).
8. **Storage**: migration 0047 on top of 0006. `users` (+ `age_band`, `limited_capacity`, `dob_ciphertext`, `email_ciphertext`), `identities` (phone and federated subjects, ciphertext + blind index), `devices`, `session_families`, `sessions` (one row per refresh token), new `auth_sessions`, `otp_challenges`, `otp_send_log`, `age_gate_blocks`, `age_gate_passes`, `auth_nonces`, `passkey_challenges`, `passkey_credentials`. RLS enabled on all; pre-account tables are `system` only; adapters elevate with `set_config('app.role','system', true)` per transaction (the persistence convention).
9. **Social sign-in** keys come from `CachingJwksKeyFetcher` over a `JwksHttp` port: fixed endpoints per provider, https only, host allow-list, no credentials or ports, `Cache-Control: max-age` clamped to [5 min, 24 h], one forced refresh per unknown `kid` with a 10 s cooldown, single in-flight fetch, 64 KiB cap, 5 s timeout, redirects never followed, RSA keys only. `NodeJwksHttp` resolves DNS itself and refuses private, loopback, link-local, CGNAT, multicast and reserved addresses.
10. **Passkeys** use `@simplewebauthn/server` v14: origin and RP ID from config, user presence and user verification both required, single-use challenge with 5 min TTL, counter regression marks the credential `suspected_clone` and revokes every session, BE flag is pinned per credential, BS stored. The `userHandle`, when the authenticator returns one, must equal the credential owner's user id.
11. **Attestation and SMS** stay behind ports (`attestation.app-attest`, `messaging.sms-whatsapp`). Unconfigured adapters answer 503 `provider_not_configured`; `attestDevice` re-throws that error instead of reporting "device untrusted". Dev fixtures remain dev-only.
12. **Age**: DOB is evaluated once at the gate; the pass stores only the band (`18_20`, `21_plus`) and an encrypted DOB for at most 24 h; the account copies both. 18 to 20 sets `limited_capacity`. Under 18 creates no account and blocks device key, device id hash and keyed DOB for 30 days.

## Consequences
- Production auth composes with real Postgres stores and the real token service; with no providers configured it fails closed (401 on bearer routes, 503 on sign-in paths) instead of faking success.
- Events: `session.revoked` and `user.age_blocked` are appended to `outbox_events` by `KyselyAuthEventPublisher` in their own transaction right after the state change, not in the same one (the `SessionRepository` port carries no event). A crash between the two loses one notification. Fix: pass events into `compareAndSave/save` and write them in the same transaction (open item).
- Operators must still provide: KMS adapter, secret-manager key source, App Attest / Play Integrity verifier, SMS/WhatsApp providers. No environment variable path exists for the signing keys yet (config surface is outside this change).
