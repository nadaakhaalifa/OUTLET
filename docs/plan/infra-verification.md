## Prometheus tests (`infra/observability/prometheus/tests/*.test.yaml`)
Generated by `tooling/infra/gen-prom-tests.py` (synthetic counters, 600 events/min, 1 minute scrape). Per SLO:
- a fast burn (error ratio just above the fast threshold, 1h and 5m windows) fires the page alert, and does not fire before the window fills;
- a slow burn just under the fast threshold fires only the slow alert (6h and 30m windows), honours `for: 15m`;
- a ratio just above the slow threshold fires it, just under (0.9x) fires nothing;
- a healthy period fires nothing;
- both alerts resolve once the short window clears;
- recording rules `slo:sli_error:ratio_rate{5m,30m,1h}` and `slo:sli_events:rate*` equal 0.25 and 10/s for a steady 25% bad series;
- the `NoData` alert (api, checkout, search) fires only after the `for` delay on an empty input;
- reconciliation: zero is healthy, non-zero fires the ticket alert after 5m and the page alert after 24h, and resolves.
Expected labels and annotations are read from the rule files, so the tests pin thresholds and timing, not label text.

Mutation sanity check on `slo-search-latency`: raising or lowering the fast threshold, the slow threshold, the long window, the short window, or either `for:` made `promtool test rules` fail (an earlier version of the tests missed three of these; the cases above were added to kill them). Mutating only one window of a two-window `and` is not detectable by design, the other window still gates.

## Rego tests (`infra/terraform/policy/terraform_test.rego`)
31 tests cover every deny rule (db encryption, public, backups; cache transit and at-rest; KMS rotation; each of the 4 public-access-block attributes; bucket without block; secret version; world ingress; access key; hard-coded region incl. aliased provider) and the single-AZ warning, each with a violating and a compliant fixture, plus an all-compliant document and empty input. A mutated policy (KMS rule disabled) made 2 tests fail, so the tests are not vacuous.

Fixture shape caveat: the policy runs on `conftest --parser hcl2` output of the `.tf` source (`input.resource.<type>.<name> = [ {attrs} ]`), not on `terraform show -json` plan output (`resource_changes[].change.after`). The fixtures follow the shape the policy actually consumes (checked against `conftest parse modules/postgres/main.tf`) and were written by hand; no `terraform plan` was run (no cloud credentials). Policy limitation found: attribute values that are variables (for example `backup_retention_period = var.x`) parse as the string `"${var.x}"`, so the backup rule can only catch a literal 0.
