# CI/CD, supply chain and quality gates

Spec refs: A2, T5 (supply chain), T7, T11, P1. Owner: platform. Status: implemented as workflow
files; **no workflow has run on GitHub yet** (the repository has no remote Actions history). Treat
every item below as "written, locally validated where stated, unproven in CI".

## Pipelines

| Workflow | Trigger | What it does |
|---|---|---|
| `ci.yml` / verify | PR, push to main | frozen-lockfile install, `pnpm typecheck`, `pnpm lint`, `pnpm test` |
| `ci.yml` / boundaries | PR, push | `pnpm depcruise` (A2.3 rules, see architecture-fitness.md) |
| `ci.yml` / i18n-parity | PR, push | unit tests of the checker, then `pnpm i18n-check` (AR/EN key parity, A2.15) |
| `ci.yml` / secret-scan | PR, push | gitleaks over full history, config `.github/gitleaks.toml` |
| `ci.yml` / dependency-audit | PR, push | `pnpm audit --audit-level high --prod` and OSV scanner on the lockfile |
| `ci.yml` / iac | PR, push | `terraform fmt -check`, `init -backend=false` + `validate` per environment, Conftest, Checkov |
| `ci.yml` / mutation | push to main, or PR label `run-mutation` | Stryker on `packages/domain`, report uploaded as an artifact |
| `codeql.yml` | PR, push, weekly | CodeQL `security-extended` for JavaScript/TypeScript |
| `sbom.yml` | push to main, reusable | CycloneDX 1.6 SBOM from the pnpm lockfile (`cdxgen`), uploaded as an artifact |
| `release.yml` | tag `v*.*.*`, manual | build image, CycloneDX image SBOM, keyless cosign signature and SBOM attestation, SLSA provenance via `slsa-github-generator`, verification job |

## Local commands

```sh
pnpm typecheck && pnpm lint && pnpm test
pnpm depcruise        # needs Node 22, 24 or >= 26; .nvmrc pins 24
pnpm i18n-check
pnpm mutation         # about 4 minutes, see mutation-testing.md
```

## Required branch protection (cannot be expressed in files)

Set these once in GitHub repository settings or a ruleset. They are the part of T11 that the
repository files alone do not enforce.

1. Protect `main`: require pull request, linear history, conventional-commit title check.
2. Required status checks: `verify`, `boundaries`, `i18n-parity`, `secret-scan`, `dependency-audit`, `iac`, `analyze` (CodeQL).
3. Require review from Code Owners. **Two approvals** on the money and security paths listed in
   `.github/CODEOWNERS`. GitHub's CODEOWNERS file picks reviewers but does not set a per-path
   approval count, so use a ruleset with "required approvals: 2" plus path restrictions, or enforce
   the count with a small status check later. Until that is configured, two-reviewer review is a
   convention, not a control.
4. Enable secret scanning push protection and Dependabot alerts (Renovate handles version PRs).
5. Create GitHub Environments `dev`, `staging`, `prod` with required reviewers on `prod`. The OIDC
   trust in `infra/terraform` is scoped to `environment:<name>` subjects.
6. Restrict who can push `v*` tags.

## Supply-chain posture and what is not yet true

* **Lockfile**: `pnpm install --frozen-lockfile` everywhere.
* **SBOM**: CycloneDX per build. The lockfile SBOM is generated by `cdxgen` via `pnpm dlx` at
  `@latest`, which is itself unpinned. VERIFY BEFORE LAUNCH: pin the version and verify its
  provenance.
* **Signing**: keyless cosign through GitHub OIDC (Sigstore public good instance). Verification
  pins the certificate identity to this repository. VERIFY BEFORE LAUNCH: that the public
  Sigstore instance is acceptable under the chosen residency regime; otherwise a private Sigstore
  or KMS-backed keys are needed (ADR-0015).
* **SLSA**: the container generator targets Build L3 provenance. T5 says "L2 to L3". Reaching and
  *claiming* L3 depends on the final build process (hosted runners only, no secret exposure to the
  build, deploy-time verification). Do not state a SLSA level externally until a deployed pipeline
  has been checked against the spec.
* **Actions pinning**: workflows use major-version tags for readability; Renovate
  (`helpers:pinGitHubActionDigests`) opens PRs to pin them to digests. **VERIFY BEFORE LAUNCH**:
  all actions are SHA-pinned before the first production release. `instrumenta/conftest-action@master`
  is an unpinned branch reference and must be replaced by a pinned release or a `conftest` binary
  install.
* **Release is inert**: `release.yml` refuses to run until `vars.CONTAINER_REGISTRY` is set and
  `apps/api/Dockerfile` exists. Neither exists. Registry choice follows ADR-0002.
* **DAST (ZAP on staging)** and **mobile build (EAS)** pipelines are not in this change: staging does not exist and EAS builds are an owner/account step.
